# Data Model: Real-Time Tracking System

## Overview

Tracking data model extending the Booking Lifecycle data model (`specs/009-booking-lifecycle-completion/data-model.md`). All entities, relationships, and enums are aligned with the backend Tracking Module as the single source of truth.

---

## Entity: `TrackingSession`

A real-time tracking session associated with an active booking. Links provider location data with booking status.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string (UUID) | Yes | Unique session identifier |
| bookingId | string (UUID) | Yes | Associated booking (FK → Booking.id) |
| status | TrackingStatus (enum) | Yes | Current session state |
| providerLatitude | number (decimal) | No | Provider's current latitude (-90 to 90) |
| providerLongitude | number (decimal) | No | Provider's current longitude (-180 to 180) |
| eta | string (ISO 8601) | No | Estimated arrival time |
| lastUpdated | string (ISO 8601) | No | When location was last updated |
| startedAt | string (ISO 8601) | No | When tracking started |
| endedAt | string (ISO 8601) | No | When tracking ended (completion or cancellation) |

### TrackingStatus Enum

| Value | Description | UI Display Color |
|-------|-------------|------------------|
| `NOT_STARTED` | Not yet initialized | Gray |
| `ACTIVE` | Tracking session is live | Green |
| `PAUSED` | Tracking temporarily paused | Amber |
| `COMPLETED` | Tracking session ended | Blue |

### State Transitions

```
NOT_STARTED → ACTIVE
ACTIVE → PAUSED
PAUSED → ACTIVE
ACTIVE → COMPLETED
PAUSED → COMPLETED
```

### Validation Rules
- Tracking session cannot be created without an associated booking
- Provider latitude must be between -90 and 90
- Provider longitude must be between -180 and 180
- `endedAt` must be after `startedAt`
- `lastUpdated` must be >= `startedAt`
- Only one active tracking session per booking at a time

## Entity: `TrackingEvent`

A chronological entry in the tracking timeline representing a state change, location update, or provider action.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string (UUID) | Yes | Unique event identifier |
| type | TrackingEventType (enum) | Yes | Category of the event |
| title | string | Yes | Human-readable event title |
| description | string | Yes | Detailed event description |
| timestamp | string (ISO 8601) | Yes | When the event occurred |
| metadata | TrackingEventMetadata | No | Event-specific data |

### TrackingEventType Enum

| Value | Description | Trigger |
|-------|-------------|---------|
| `STATUS_CHANGE` | Session status transitioned | Backend |
| `LOCATION_UPDATE` | Provider location updated | Backend |
| `MILESTONE` | Significant checkpoint reached | Backend |
| `ETA_UPDATE` | Estimated arrival time changed | Backend |

### TrackingEventMetadata

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| latitude | number | No | Provider latitude (for LOCATION_UPDATE) |
| longitude | number | No | Provider longitude (for LOCATION_UPDATE) |
| eta | string (ISO 8601) | No | Updated ETA (for ETA_UPDATE) |

## Entity: `BookingTimelineEvent` (Tracking Extension)

The existing `BookingTimelineEvent` entity (from 009 data model) includes these tracking-related event types:

| Tracking-Related Type | Description | Display |
|-----------------------|-------------|---------|
| `TRACKING_STARTED` | Tracking session initiated | Navigation icon |
| `LOCATION_UPDATED` | Provider location updated | MapPin icon |

These events are generated by the backend when tracking state changes and are consumed via `GET /bookings/:id/timeline`.

---

## Entity: `TrackingNotification` (Notification Extension)

Tracking notification types extending the existing `CustomerNotificationType` enum.

### New Notification Types

| Type | Trigger Event | Audience | UI Icon | Navigation |
|------|---------------|----------|---------|------------|
| `TRACKING_STARTED` | Provider starts route | Customer | Navigation | `/client/tracking/:bookingId` |
| `TRACKING_PAUSED` | Provider pauses tracking | Customer | PauseCircle | `/client/tracking/:bookingId` |
| `TRACKING_RESUMED` | Provider resumes tracking | Customer | PlayCircle | `/client/tracking/:bookingId` |
| `TRACKING_ARRIVED` | Provider arrives at location | Customer | MapPin | `/client/tracking/:bookingId` |

### Notification Type Union (Updated)

```typescript
type CustomerNotificationType = 
  | 'BOOKING_UPDATE' | 'BOOKING_CREATED' | 'BOOKING_ACCEPTED' 
  | 'BOOKING_ASSIGNED' | 'BOOKING_STARTED' | 'BOOKING_COMPLETED' 
  | 'BOOKING_CANCELLED' 
  | 'TRACKING_STARTED' | 'TRACKING_PAUSED' | 'TRACKING_RESUMED' | 'TRACKING_ARRIVED'
  | 'ANNOUNCEMENT' | 'PROMO' | 'SYSTEM';
```

### Metadata

All tracking notification types carry `bookingId` in metadata for navigation to the tracking page.

## Relationships

```
Booking (1) ──── (1) TrackingSession
Booking (1) ──── (N) BookingTimelineEvent
TrackingSession (1) ──── (N) TrackingEvent
Booking (1) ──── (N) BookingNotification (includes tracking types)
```

---

## State Machine: Tracking + Booking Interplay

```text
Booking: ON_THE_WAY ───→ Tracking: ACTIVE ───→ Booking: IN_PROGRESS
Booking: IN_PROGRESS ───→ Tracking: ACTIVE/PAUSED
Booking: IN_PROGRESS ───→ Booking: COMPLETED └── Tracking: COMPLETED
Booking: CANCELLED ─────→ Tracking: COMPLETED (auto)
```
